# Config Studio — Antigravity & Gemini Project Rules 🚀

## 🗺️ Регламент ведения ROADMAP.md (Roadmap Clean-State Discipline)

**ОБЯЗАТЕЛЬНОЕ ПРАВИЛО ДЛЯ ВСЕХ СЕССИЙ:**
1. **Только незавершенные задачи наверху:** Секции текущего спринта и бэклога (`## 🎯 ТЕКУЩИЙ ЭТАП / В РАБОТЕ` и `## 🖧 ПЛАНИРУЕМЫЕ ПЛАГИНЫ`) должны содержать **строго невыполненные задачи (`- [ ]`)**.
2. **Всегда переносить выполненное под спойлер:** Как только этап, плагин, фича или пункт бэклога завершается, его **ВСЕГДА необходимо переносить вниз под спойлер `<details><summary>...</summary></details>` в раздел `## 📦 АРХИВ ВЫПОЛНЕННЫХ ЭТАПОВ (Released)`**.
3. **Верхний план никогда не захламляется:** Верхняя часть дорожной карты должна оставаться чистой, компактной и наглядной, отражая только актуальный фронт работ и предстоящие задачи.
4. **Обновлять сводную таблицу релизов:** При закрытии пакета задач добавлять новую строку с версией в сводную таблицу релизов внутри спойлера `✅ Сводный список выпущенных версий`.

## 🛠️ Главные регламенты разработки

1. **Сперва ядро (Core First):** Сначала механизмы ядра редактора, API и точек расширения.
2. **Предварительное обсуждение:** Перед реализацией каждой отдельной функции обязательно обсуждать её UX/UI, структуру данных и сценарии с пользователем.
3. **One Repo Per Plugin:** Каждый официальный плагин разрабатывается в отдельном GitHub-репозитории организации `config-studio`.
4. **Инженерная дисциплина (/ub-mode):** *First Make it Work* (Laziness Protocol, TDD, Idempotence), *Then Make it Right* (устранение первопричин, дробление, удаление мертвого кода), *Follow Practice* (Worktree Cleanup, Keep a Log, Commit often with proof).
